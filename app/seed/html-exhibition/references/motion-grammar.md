# 动效语法

动画必须表达信息，而不是填补空白。先确定动作对应的真实机制，再选择实现。

## 两类动画

- 概念动画：用稳定视觉隐喻解释输入、状态、分支和输出；每个动作必须能追溯到已验证事实。
- 通用动效：用于进入、强调和分组节奏，不承担机制解释。

## 性能边界

动画关键帧只修改 `transform` 和 `opacity`。移动用 `translate`，缩放用 `scale`；不得动画 `width`、`height`、`top`、`left`、`margin` 或 `padding`。所有动画必须提供 `prefers-reduced-motion` 静态终态。

## 语义映射

| 动效 | 意义 | 约束 |
|---|---|---|
| `anim-rise` | 新内容进入 | 标题或主要内容 |
| `anim-fade` | 补充信息出现 | 不制造方向暗示 |
| `anim-pop` | 唯一重点 | 每页最多一处 |
| `stagger` | 并列信息按序阅读 | 组内最多 5 项 |
| `cursor` | 终端语气点缀 | 全场最多两处 |
| `data-fragment` | 演讲者控制的信息增量 | 由统一运行时处理 |

## 两种观看方式

- `scroll`：进入视口后触发；方向键和翻页笔滚到相邻章节。
- `stage`：当前页可见，下一次前进先显示未显示的 `data-fragment`，再切页。

不要自行实现第二套键盘导航。概念动画监听运行时的 `deckchange` 事件或使用 `MX.onEnterView`。一页一个动画主角，重播按钮不得抢占 Space 的翻页语义。

## 自检

1. 每个概念动作是否对应真实事实？
2. 去掉动画后，信息是否仍可理解？
3. 是否只动画 `transform` / `opacity`？
4. 减少动态效果时是否有清晰静态终态？
5. 分步内容是否使用统一的 `data-fragment` 契约？
