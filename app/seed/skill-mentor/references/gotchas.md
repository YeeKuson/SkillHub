# Gotchas：真实失败模式

## 1. 把危险字符检测应用到整个 Skill 正文

**现象**：只要 Markdown 或脚本示例出现 `|`、`;`、`&&`、反引号或 `$()`，审计就直接终止。

**根因**：混淆了“把不可信输入作为命令执行”和“把代码当作数据审计”。合法 Shell Skill 必然包含这些字符。

**避免**：路径通过 literal 参数传递；只对准备执行的外部命令文本做阻断。正文出现危险字符时分析上下文、数据流和意图，但绝不执行。

**验证**：使用一个含 `git status | Select-String` 教学示例的良性 Skill，检查器可以给出线索但不得判定命令注入并停止整个审计。

## 2. 外部扫描器没运行，却写成“安全扫描通过”

**现象**：环境没有 SkillSpector，报告仍显示三层安全扫描 PASS。

**根因**：把“没有工具输出”误当成“工具没有发现风险”，掩盖覆盖缺口。

**避免**：为每层使用 `PASS/FAIL/NOT_RUN/NOT_APPLICABLE`；外部扫描缺失时标记 `DEGRADED`，执行本地静态和语义检查，并降低结论置信度。

**验证**：在找不到 `skillspector` 的环境运行 Audit，报告必须包含 `L1=NOT_RUN`，且不能写“已证明安全”。

## 3. description 写进了完整流程，Agent 只走捷径

**现象**：description 概括了所有步骤，Agent 根据短描述直接行动，没有加载和遵循正文中的门禁、异常或验证规则。

**根因**：元数据本应解决触发，却变成了主流程的低保真副本。

**避免**：description 重点写能力、触发上下文和排除条件；详细顺序、门禁和异常只在正文保留一个权威版本。

**验证**：使用不点名 Skill 的复杂正例，检查 Agent 是否加载正文并输出其中独有的证据字段；再用相邻反例检查不过度触发。

## 4. 为了获得加分而制造无用目录和记忆

**现象**：Skill 新增空 `references/`、未调用脚本或没有生命周期的 memory 文件，只为了满足检查表。

**根因**：指标取代目标，产生 shape-bake 和维护负担。

**避免**：加分要求资源有真实职责、被主流程引用且经过验证；不需要持久状态时将记忆机制标为 N/A。

**验证**：删除该资源后若触发、决策、执行、验证和输出均不变，则不得加分，并应把它列为候选冗余。

## 5. 总分与 HIGH 问题互相打架

**现象**：报告列出 HIGH 断链或安全风险，却给出 S 级并建议上架。

**根因**：先打印象分，后补问题清单，没有执行一致性门禁。

**避免**：先形成 finding，再评分，最后执行等级封顶和安全否决。普通 HIGH 质量问题最高 A；安全 HIGH/CRITICAL 强制 FAIL 和 `DO_NOT_INSTALL`。

**验证**：使用含断链和疑似凭证的夹具，报告等级与发布建议必须按门禁自动收紧。
