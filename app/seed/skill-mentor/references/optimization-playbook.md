## 授权门禁

把“分析、审计、优化建议”与“修改文件”分开。用户未明确要求改写时，只给方案。获得授权后仍要说明目标、文件、影响、风险和验证，再创建可恢复备份。

备份必须：

- 位于目标 Skill 目录之外，避免被当成资源扫描或安装。
- 保留原目录结构、时间和来源版本。
- 不包含额外读取到的真实秘密。
- 在报告中记录位置；不得自动删除备份。

如果无法安全备份，停止修改并只提供补丁建议。

## 建立基线

优化前冻结以下证据：

- 原 Skill 快照或版本标识。
- 触发正例、反例和边界例。
- 功能输出与客观断言。
- 安全发现、八维分数和九项审计。
- 可获得时记录 token、工具调用、耗时和失败率。

不要用改写后的评测标准证明改写成功。新增评测可以补充，但原基线必须保留。

## 单变量循环

默认最多 5 轮；用户可明确提高，硬上限 100 轮。每轮执行：

1. 从一个 finding 提出可证伪假设。
2. 选择最小修改面，只解决该假设。
3. 运行直接相关评测，并保留关键全量回归。
4. 与未修改基线比较，不只看单次输出。
5. 记录结果：改善、无变化、退化或证据不足。
6. 改善则保留；退化则回滚；证据不足则设计下一实验，不叠加盲改。

记录模板：

```text
轮次：N
Finding：D1-001
假设：增加反触发条件会降低无关任务误触发率，不降低正例触发率
唯一改动：重写 description 的排除条件
基线：正例 8/10，反例误触发 4/10
结果：正例 9/10，反例误触发 1/10
决定：保留
证据：evals/...、运行命令、时间
```

## 保留与回滚

- 只有目标指标改善且安全、结构和关键功能不退化时才保留。
- 出现新 HIGH/CRITICAL、安全结论变差或核心评测失败时立即回滚该轮。
- 不能只因总分上升保留改动；总分可能掩盖触发或安全退化。
- 回滚只恢复本轮变更，不覆盖用户在循环外的并行修改。
- 每轮后检查工作区差异，确保没有无关格式化或孤儿文件。

## 常见优化方向

| 现象 | 首选改动 | 验证 |
|---|---|---|
| 低触发 | 补真实用户措辞、近义词、任务上下文 | 正例和释义正例触发率 |
| 过度触发 | 加排除条件、收窄问题域 | 无关反例误触发率 |
| 加载后走错分支 | 写可观察谓词和默认分支 | 边界用例路由准确率 |
| 输出缺字段 | 使用正向输出契约或结构槽位 | Schema/断言完整率 |
| 规则在压力下被跳过 | 加红旗、停止条件和反合理化 | 组合压力场景遵从率 |
| 内容过长 | 外移重参考、删除重复、直接引用 | SKILL 行数、token、检索成功率 |
| 静态安全误报 | 增加上下文判定与组合规则 | 已知良性/恶性夹具的精确率与召回 |

优先写“应该产生什么”的正向契约；仅在 Agent 明知规则却在压力下绕过时使用强制禁令和反合理化表。

## 停止条件

满足任一条件停止：

- 成功标准已达到且全量回归通过。
- 连续两轮没有指标改善，需要新信息或不同设计。
- 达到用户批准的迭代上限。
- 出现授权、环境、安全或数据阻塞。
- 下一步需要安装、发布、迁移、删除或扩大权限，超出当前授权。

停止不等于完成。报告当前最佳版本、未解决问题、回退状态和下一步需要的授权。
